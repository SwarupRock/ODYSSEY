SCOPE AND RESTRICTIONS
----------------------
This was a read-only regression audit following Stages 4B, 4B.1, and 4C.
The authoritative project documents, all seven chapter scenes, shared input
and lifecycle modules, styles, and root/Android packaged JavaScript were
inspected.

No gameplay source, styles, assets, configuration, save data, APK, commit,
or branch state was modified. The only created file is this requested audit
report. No fixes were applied.

EXECUTIVE SUMMARY
-----------------
The integration branch and expected HEAD are correct. The seven scene classes
remain present, JavaScript syntax is valid, and the audited root/Android scene
and shared runtime files are byte-identical except for a trailing-newline-only
difference in js/updater.js.

The shared keyboard and touch routing is broadly consistent with the approved
mapping. Chapter I and VI retain shared MovementController running/dodge
integration. Chapter III remains contextual and does not enable the generic
combat cluster. Chapter V keeps Space/Enter rhythm strikes separate from W/S
steering, and its cancellation path releases held notes.

Three confirmed medium findings require follow-up:

1. Bow visibility is owned globally by Gear ownership in main.js and is not
   constrained to scenes/phases that support bow use. A replaying player who
   owns a bow can see the BOW button in unsupported exploration chapters and
   non-combat phases.
2. Chapter IV and Chapter V use lowercase engine.w/engine.h in VFX and
   coordinate calculations, while Engine defines uppercase W/H. This causes
   undefined/NaN visual coordinates in affected encounter effects.
3. Chapter V's strait collision effects use lowercase dimensions, so the
   six-loss progression is recorded but the associated effect placement is
   unreliable.

The third item is grouped with the second root cause in the severity count
below; it is listed separately in the chapter findings because it affects a
different gameplay section.

SEVERITY AND CLASSIFICATION
---------------------------

M1 — MEDIUM — CONFIRMED DEFECT
File/function: js/main.js:214-218 beginScene; js/stick.js:180-190
Description:
Stick.refreshBow() is called globally when any chapter begins and only checks
Gear.kit().bow.power. It does not check whether the active scene or phase
supports bow use. Consequently an owned bow can remain visible during
unsupported chapters and exploration/non-combat phases. Chapter I's stealth
phase is an explicit example: its scene-level refresh occurs only when the
fight starts, but beginScene has already refreshed the global button.
Impact:
The UI advertises an action outside its approved availability rules. Chapter
III, IV, and V do not implement a bow action handler; Chapter VI also leaves
the bow button visible after combat victory. Keyboard B is ignored or may
remain accepted by a scene handler even when the phase is no longer combat.
Classification: Confirmed defect.

M2 — MEDIUM — CONFIRMED DEFECT
File/function: scenes/ch4_underworld.js:80,98,146; Engine exposes W/H in
js/engine.js:13-16 and resize()
Description:
Chapter IV uses this.engine.w instead of this.engine.W for ghost and loot
effect coordinates. The values are undefined in the current Engine.
Impact:
Ghost spawn and Achilles reward VFX receive invalid x coordinates. Narrative
progression and Save completion still execute, but the affected visuals are
not reliable.
Classification: Confirmed defect.

M3 — MEDIUM — CONFIRMED DEFECT
File/function: scenes/ch5_straits.js:121,272; Engine exposes W/H in
js/engine.js:13-16 and resize()
Description:
Chapter V rhythm judgment effects and strait collision effects use lowercase
engine.w/engine.h. The six-loss value is explicitly saved as lost: 6 in
straitVictory(), but effect coordinates can become undefined/NaN.
Impact:
Rhythm feedback and Scylla/Charybdis collision VFX may be misplaced or absent.
The approved six-crew-loss progression itself is preserved.
Classification: Confirmed defect.

I1 — INFORMATIONAL — DESIGN DISCREPANCY
File/function: scenes/prologue.js:1-110
Description:
The Prologue contains the cinematic march, dialogue, and a short follow walk.
It has no optional Trojan Captain encounter or introductory combat routing,
although the GDD describes those as proposed Prologue gameplay.
Impact:
The section does not currently provide the complete GDD tutorial/combat
target. This is not a regression introduced by Stages 4B-4C and should not be
treated as an input-lifecycle failure.
Classification: Design discrepancy / existing limitation.

I2 — INFORMATIONAL — EXISTING LIMITATION
File/function: js/updater.js root and Android packaged copy
Description:
The only unexpected parity mismatch among the audited JavaScript files is a
single trailing newline difference. Content and behavior are identical.
Classification: Existing packaging limitation; no functional impact.

I3 — INFORMATIONAL — UNABLE TO VERIFY
File/function: all chapter runtime paths
Description:
Physical Android WebView execution was not performed, and the browser was
blocked by the active mandatory update gate. Browser DOM/lifecycle state was
inspectable, but full chapter traversal and physical touch gestures were not
available.
Classification: Unable to verify.

CROSS-CHAPTER KEYBOARD FINDINGS
--------------------------------

Approved mapping inspection:
- A/D and arrows are continuous axis movement in Engine.axisX().
- Shift is polled only by the supported Chapter I/VI controller movement
  paths; it is not an action dispatch.
- Space/Enter remain scene-specific contextual/light actions.
- C/K are globally routed to "dodge" in main.js:367-371.
- F/R/L/I/U are passed to scene-specific handlers.
- B is globally routed to "bow" at main.js:363-366.
- J remains isolated to MovementTestScene.
- W/S remain axis input and Chapter V uses axisY() for steering.

No source-level collision was found between A/D movement and dodge, Shift and
dash/dodge, K and spin, or W/S steering and Chapter V rhythm strikes.
Chapter-specific handlers generally guard unsupported actions. Bow availability
is the exception documented as M1.

CROSS-CHAPTER TOUCH AND LIFECYCLE FINDINGS
------------------------------------------

- Stick uses explicit interactive gating, per-button pointer ownership, and
  joystick pointer ownership in js/stick.js:12-239.
- Dialogue.show() disables touch interaction and resets held controls;
  Dialogue.hide() restores interaction only while Stick.inGame is true
  (js/ui.js:35-57 and :94-103).
- Engine.resetInput() clears keys, canvas pointer state, joystick axes, and
  broadcasts an odyssey-input-reset event (js/engine.js:114-123).
- Engine.setScene() cancels the outgoing scene before resetting input
  (js/engine.js:100-112).
- Window blur and document visibility loss reset the touch rig.
- Pointercancel/pointerleave paths clear joystick/button state and ChapterScene
  input holds. Chapter V has a specialized cancellation path that does not
  judge an interrupted hold as a miss.
- Screen/update-lock state disables touch controls through setInGame(false).
  Browser inspection confirmed the active mandatory update lock rendered the
  gameplay controls with aria-disabled=true and pointer-events:none.
- Full physical pointer traversal was unavailable because the browser was
  update-locked and no Android runtime was used. Therefore lifecycle behavior
  is source-verified plus limited DOM-verified, not full runtime-proven.
