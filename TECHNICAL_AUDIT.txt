A. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
ODYSSEY is an operational, highly-optimised 2D action-adventure web game embedded in 
an Android native WebView shell. The code is written in clean, modern vanilla JavaScript 
(ES Modules) without external npm runtime dependencies or frameworks. 

The baseline release (v1.0.0) is stable and playable from Prologue through Chapter VI. 
However, the gameplay across chapters currently relies on chapter-specific, ad-hoc 
interaction loops rather than unified shared systems. The project is now embarking on 
an incremental modernization following the approved Game Design Document (GDD) and 
Final Gameplay Systems Specification.

Key Strengths:
  - Lean footprint (~250KB code/styling; ~3.6MB voice files; zero bitmap/audio asset bloat).
  - Robust zero-permission offline architecture via AndroidX WebViewAssetLoader.
  - Expressive procedural canvas rendering with custom palette and lighting effects.
  - Multi-tier speech synthesis architecture (MP3 voiceover -> AndroidTTS -> Web Speech API).

Primary Technical Challenges for Modernisation:
  - Input & Lifecycle: Incomplete pointercancel handling and lack of input blocking 
    during dialogue create risks of stuck states and unintended actions.
  - Movement & Traversal: Currently fragmented across scenes; grounded jumping, 
    coyote time, and unified running do not exist in the engine yet.
  - Combat & Stamina: Existing combat is mostly visual VFX (`js/combat.js`) and 
    isolated chapter combat scripts; a unified lightweight stamina model (100 max, 
    regeneration delay, dodge/parry costs) has not yet been implemented.
  - Save Versioning: Current `Save` object does not track save schema versions, 
    checkpoints within chapters, or complex narrative flags.

C. EXISTING ARCHITECTURE
--------------------------------------------------------------------------------
1. Game Loop & Scheduling (`js/engine.js`):
   - Driven by `requestAnimationFrame`. Delta time (`dt`) is capped at 0.1s to prevent 
     spiral-of-death tunneling.
   - [VERIFIED] Includes a fallback interval timer (`setInterval` at 33ms) that forces 
     simulation steps if `performance.now() - this.lastT > 220ms` (handles backgrounded 
     tabs and aggressive mobile throttling).
   - Hit-stop mechanic (`engine.hitStop(sec)`) freezes frame updates for brief intervals 
     to provide tactile impact feedback on heavy attacks.

2. Scene Lifecycle (`js/scenefw.js` & `js/main.js`):
   - `main.js` manages scene transitions via `startNext()` and `playChapter(idx)`.
   - `ChapterScene` provides `initState()`, `intro()`, `tick(dt)`, `draw(ctx)`, and `cleanup()`.
   - [VERIFIED] Base class automatically initialises chapter-specific visual styles in `Fx.setStyle()`.
   - Cleanup is handled in `finish(extra)` by hiding HUD elements and invoking optional scene `cleanup()`.

3. Input Handling (`js/engine.js` & `js/stick.js`):
   - Desktop: Keyboard listener binds `keydown`/`keyup` to a `Set` (`engine.keys`). Continuous 
     movement axes `axisX()` and `axisY()` map WASD and arrow keys to [-1, 1].
   - Touch/Mobile: `js/stick.js` manages a dynamic on-screen floating joystick updating 
     `engine.stickX` and `engine.stickY`. Action buttons (`#btn-act` and `#btn-bow`) dispatch 
     virtual key events (`" "` and `"bow"`).
   - Gestures: `engine.js` detects taps (duration < 600ms, movement < 12px) and directional 
     swipes (distance > 24px, duration < 450ms).

4. Rendering Pipeline (`js/art.js` & `js/fx.js`):
   - Canvas resolution matches device pixel ratio up to `DPR = 2` for high-DPI crispness.
   - Camera transforms world coordinates to screen space with automatic viewport zoom 
     scaling (`zoom = Math.min(W / 840, H / 520)`).
   - Post-processing overlay (`Fx.end(ctx)`) applies a unified pass of vignette, film grain, 
     dust/ember particles, god rays, and dynamic hero rim-lighting (`Fx.hero()`).

E. INPUT AND MOVEMENT AUDIT
--------------------------------------------------------------------------------
1. Pointer Cancellation [VERIFIED RISK]:
   - In `js/engine.js`:
     ```javascript
     c.addEventListener("pointercancel", () => { this.pointer.down = false; this.dragging = false; });
     ```
   - In `scenes/ch1_cyclops.js`, `scenes/ch2_winds.js`, `scenes/ch3_circe.js`, and `scenes/ch4_underworld.js`:
     The scenes track their own private hold variables (`_holdDir`, `holdDir`, `hold`).
   - When a system gesture, incoming phone call, or OS prompt fires `pointercancel`, `engine.pointer.down` 
     resets, but `scene.onPointerUp()` is NEVER called.
   - Result: Characters can become stuck moving indefinitely in the last held direction until another touch occurs.

2. Dialogue Input Restriction [VERIFIED RISK]:
   - When dialogue appears, `document.body.classList.add("dlg-open")` is set, which visually dims 
     `#touch-controls` to opacity 0.22 in CSS.
   - However, `pointer-events: none` is NOT applied to `#touch-controls` or the canvas.
   - As a consequence, players can continue pressing the virtual joystick or tapping action buttons 
     while dialogue boxes are active, causing background character movement or unwanted weapon swings.

3. Chapter-Specific Movement Fragmentation [VERIFIED]:
   - Prologue: Fixed cinematic script; movement is simple 1D `playerX` addition.
   - Chapter I: Discrete grid/lane movement with custom dragging speed.
   - Chapter II: Rotational ship steering physics (`steerAngle`, `windAngle`).
   - Chapter III: Continuous 2D plane movement with herb collision checks.
   - Chapter V: Vertical steering lane selection.
   - Chapter VI: 1D horizontal combat arena movement with dodge roll state.
   - Assessment: There is no shared movement controller class. Jumping, grounded physics, 
     and variable-height leaps do not exist anywhere in the engine.

F. COMBAT AND EQUIPMENT AUDIT
--------------------------------------------------------------------------------
1. Combat State Architecture [VERIFIED]:
   - Currently, `js/combat.js` is not a gameplay state machine; it is solely an effects 
     manager (`Cinematic.slash`, `Cinematic.sparks`, `Cinematic.impact`, `Cinematic.arrowTrail`) 
     plus the non-interactive `FilmIntro` sequence.
   - Combat logic is implemented directly inside `scenes/ch6_ithaca.js` (melee duel vs Antinous) 
     and `js/scenefw.js` (bow shooting and arrow hit registration).
   - Stamina: There is NO stamina property or tracking in `Engine`, `ChapterScene`, or `Save`.
   - Parrying: No active timed-parry system exists.

2. Equipment and Progression (`js/gear.js`) [VERIFIED]:
   - Defines tiered arrays:
     * `ARMOR`: Linen Chiton (0) -> Aegis Half-Cape (1) -> Armor of Achilles (2).
     * `SWORDS`: Bronze Xiphos (0) -> Moly-Tempered Blade (1) -> Sword of Hector (2).
     * `BOWS`: None (0) -> Great Bow of Odysseus (1).
     * `ARROWS`: Broadhead Shafts (0) -> Fire Arrows (1) -> Arrows of Apollo (2).
   - Supports down-equipping (`gear.swordEq`, `gear.arrowEq`) while preserving ownership.
   - Weapon damage values and visual FX are wired up, but special gameplay attributes 
     (e.g., moly magic mitigation, crowd-cleave effects) are currently hardcoded or cosmetic.

G. SAVE SYSTEM AUDIT
--------------------------------------------------------------------------------
1. Storage Engine (`js/engine.js` -> `Save`) [VERIFIED]:
   - Storage medium: Browser `localStorage` under key `"odyssey-save-v1"`.
   - Current schema structure:
     ```javascript
     {
       unlocked: 1,       // Number (1-based chapter unlock index)
       hubris: 0,         // Number (accumulated hubris score)
       completed: [],     // Array<Number> (indices of finished chapters)
       best: {},          // Object (per-chapter high score / performance metrics)
       gear: {            // Object (stored by Gear.load())
         armor: 0,
         sword: 0,
         bow: 0,
         arrow: 0,
         swordEq: 0,
         arrowEq: 0
       }
     }
     ```
2. Save Migration & Robustness Risks:
   - [VERIFIED] Schema versioning is absent. If data structures expand in Phase 4 (e.g., adding 
     `checkpoints`, `narrativeFlags`, `crewMorale`, `crewTrust`), existing user saves will 
     require explicit schema migration logic to avoid overwriting or corruption.
   - [VERIFIED] `Save.load()` performs `Object.assign(this.data, JSON.parse(raw))`. This creates a 
     shallow merge; nested structures like `best` and `gear` can lose new default properties.
   - [VERIFIED] In-chapter checkpoints do not exist. Reloading always restarts the current chapter.

H. ANDROID AND WEB COMPATIBILITY
--------------------------------------------------------------------------------
1. Android Native Shell (`android/app/.../MainActivity.java`) [VERIFIED]:
   - Security: Zero-permission manifest. No internet socket or network access.
   - Asset Delivery: Uses `WebViewAssetLoader.AssetsPathHandler` mapping `app/src/main/assets/` 
     to `https://appassets.androidplatform.net/assets/`. This resolves all modern ES module 
     CORS and origin restrictions locally.
   - Hardware Back Button: Managed via AndroidX `OnBackPressedCallback`. Single back press 
     evaluates `window.odysseyBackPress()` (advances dialogue); double back press within 900ms 
     finishes the activity (`finish()`).
   - Android TTS Bridge: Native `AndroidTTS` object bound via `@JavascriptInterface`, allowing 
     Java `TextToSpeech` execution when Web Speech API is absent or deprioritized.
   - Lifecycle: `onPause()` calls `web.pauseTimers()` and `web.onPause()`, halting RAF 
     and background CPU consumption cleanly.

2. Web & PWA Architecture [VERIFIED]:
   - Offline Service Worker: `sw.js` caches core static assets on install.
   - PWA Voice Limitation [VERIFIED RISK]: `sw.js` explicitly caches code, css, and fonts, 
     but does NOT precache the 94 voice clips in `audio/voices/` (total ~3.6MB). In web browser 
     PWA mode, voice playback falls back to Web Speech API when offline unless clips were 
     previously cached via background fetch.
   - Gamepad Support [VERIFIED ABSENCE]: Documented in legacy summaries, but confirmed 100% 
     absent in engine code. No `navigator.getGamepads()` calls exist.
